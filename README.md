# price-gap-research

楽天市場・Yahoo!ショッピングで仕入れて eBay で販売した場合の利益を調べる Web アプリです。

楽天・Yahoo! の商品を公式 API で一括取得し、JAN コード・カード番号・検索キーワードで同じ商品を見分けて eBay の相場（公式 [Browse API](https://developer.ebay.com/api-docs/buy/browse/overview.html) の出品中価格）と照合し、利益の条件を満たす「お宝商品」を一覧にします。

## 必要なもの

- [Node.js](https://nodejs.org/) 22 以上（`node -v` でバージョンを確認できます）

## 使い方（ローカルで動かす）

```bash
npm install      # 初回のみ：必要なライブラリをインストール
npm run dev      # 開発用サーバーを起動
```

ブラウザで http://localhost:3000 を開きます。止めるときはターミナルで `Ctrl + C` を押します。

検索条件・お宝の条件・計算条件・最後の結果は、そのブラウザの中（localStorage）だけに保存されます。

## eBay API キーの設定

1. `.env.example` をコピーして `.env.local` を作ります（Windows: `copy .env.example .env.local` / Mac: `cp .env.example .env.local`）。
2. `.env.local` をエディタで開き、`EBAY_CLIENT_ID=` と `EBAY_CLIENT_SECRET=` の右側に eBay で発行したキーを書いて保存します。
3. `npm run dev` を起動し直します（起動中に書き換えた場合は `Ctrl + C` で止めてから再起動）。

- `EBAY_ENVIRONMENT` は `sandbox`（テスト用）か `production`（本番）です。Sandbox のキー（Secret が `SBX-` で始まる）は `sandbox`、本番のキーは `production` と組み合わせてください。Sandbox で返ってくる商品・価格はテスト用のデータです。
- キーをコピー＆ペーストしたときに、目に見えない文字（ゼロ幅スペースなど）や前後の空白が紛れ込むことがあります。アプリ側で自動的に取り除きますが、認証に失敗する場合は貼り直してみてください。

### プロキシ環境で動かす場合

社内ネットワークなど HTTP プロキシ（`HTTPS_PROXY` 環境変数）経由でしか外に出られない環境では、Node.js の `fetch` がプロキシを使うように `NODE_USE_ENV_PROXY=1` を付けて起動します（Node.js 22.21 以上）。

```bash
NODE_USE_ENV_PROXY=1 npm run dev
```

## 合言葉（ログイン）

URL を知っている第三者に eBay API の利用枠を使われないよう、サイトを開くと合言葉を求めます。合言葉は環境変数 `APP_PASSWORD` で設定します。

- 合言葉が合うと、そのブラウザは 30 日間ログインしたままになります。右上の「ログアウト」で解除できます。
- `APP_PASSWORD` を変えると、それまでログインしていたブラウザはすべてログアウトされます。
- 同じ接続元から 5 回まちがえると、15 分間ログインできなくなります（簡易的な総当たり対策）。
- **本番で `APP_PASSWORD` が未設定だと、安全のためサイトも API も使えない状態になります**（エラー表示）。`npm run dev` では未設定ならログインなしで使えます。
- 4 桁の PIN のような短い合言葉は総当たりで破られやすいので、12 文字以上をおすすめします。

## 自動リサーチ（楽天・Yahoo! × eBay）

トップページ（`/`）が自動リサーチの画面です（以前の `/research` を開いた場合もトップページに移ります）。

### 流れ

1. **国内の商品を取得**: 検索条件（プリセット）ごとに、楽天市場（最大 30 件）と Yahoo!ショッピング（最大 50 件・在庫ありのみ）を公式 API で検索します。
2. **除外**: オリパ・くじ・ローダーなどの周辺グッズ・予約品は最初から除外します。未開封BOX ではさらに、開封済み・シュリンクなし・訳あり・2BOX などの複数箱・1 パックだけの出品も除外します。検索条件ごとに除外ワードを追加できます。
3. **同じ商品を見分ける**（種類ごとに方法が違います）

   | 種類 | 識別のしかた | eBay の検索 |
   |---|---|---|
   | 未開封BOX | JAN コード（Yahoo! は API の JAN、楽天は商品名・説明文から抽出。チェックデジットも確認） | JAN（GTIN）で検索、新品のみ |
   | PSA10 | カード番号（例: `205/172`、プロモ `001/SV-P`）＋ PSA10 の表記 | 「`205/172 PSA 10 japanese`」、鑑定済み（`2750`） |
   | シングル（未鑑定） | カード番号（鑑定品は除外） | 「`205/172 japanese`」、未鑑定（`4000`） |
   | その他 | JAN コード、なければ型番（例: `DD1391-100`） | JAN または型番、新品のみ |

   カード番号はタイトルからだけ取り出します（説明文には関連する別カードの番号が書かれていることがあるため）。識別できなかった商品は eBay と照合しません。
4. **eBay の相場**: まとめた商品ごとに eBay を検索し、タイトルを確認して別の商品（カード番号違い・PSA9・カスタム品・1 パックだけ・複数箱・他の言語版など）を除いてから、最安値・安い方から 25%・中央値を出します。同じ検索は 30 分間使い回し、1 回のリサーチで調べる商品数にも上限（初期値 15、最大 30）をかけて API の利用回数を抑えます。
5. **利益の計算**（画面側で計算するので、条件を変えてもすぐに再計算されます）

   ```
   利益 = (eBay 売価 − eBay 手数料) × 為替 − (国内最安値 + 国内送料) − 国際送料
   ```

   - eBay 売価: 「お宝の条件」で選んだ値（初期値は安い方から 25%。出品中価格の中央値は実際に売れる価格より高めに出やすいため）
   - 国内最安値: 楽天・Yahoo! のうち送料込みで一番安いもの。送料別・条件付きの場合は「送料別のときの国内送料」（初期値 800 円）を足します
   - 為替・eBay 手数料: 画面の「計算条件」で変更
   - 国際送料: 検索条件ごとに設定（初期値: BOX 3,000 円・PSA10 2,000 円・シングル 1,500 円）
6. **お宝の判定**: 利益（初期値 3,000 円以上）・利益率（15% 以上）・eBay の比較件数（3 件以上。少ないと相場が当てにならないため）をすべて満たすもの。各商品には楽天・Yahoo! の購入リンク、eBay の出品中・落札済みの検索リンクを付けています。

### 商品指定（カメラ・釣具・レトロゲーム・エフェクターなど）

中古品や JAN のない商品は自動で識別できないので、**1 つの検索条件 = 1 つの商品** として登録します（種類「商品指定」）。

- 国内: 楽天・Yahoo! を「検索キーワード」で検索し、**タイトルにキーワードの単語がすべて含まれる商品だけ**を比べます（大文字・小文字・全角半角は区別しません。単語は部分一致なので「F3」は「F3HP」にも一致します）。JAN を入れると、Yahoo! は JAN で完全一致検索し、楽天は JAN が一致する商品を探します。
- eBay: 「eBay キーワード」（英語）で検索し、**タイトルに単語がすべて含まれる出品だけ**を集計します。JAN があれば先に JAN で探し、3 件未満なら英語キーワードで探し直します。
- 状態: 新品（eBay `1000`）・中古（`1500`〜`6000`。ジャンク `7000` は含めない）・すべて。新品のときは国内の「中古」と書かれた商品も除きます。
- 除外: 国内はジャンク・部品取り・故障・動作未確認・難あり・訳あり・予約など、eBay は for parts・not working・box only・lot などに加え、部品・付属品によく出る言葉（washer・adapter・cable など）を含む出品を除きます。さらに、**中央値の 30% 未満・3 倍超の出品は外れ値として除外**します（タイトルの条件をすり抜けた部品や、まとめ売り対策）。
- レトロゲームは eBay で「ソフトのみ」と「箱説付き」が混ざるので、eBay キーワードに `cartridge only` や `CIB`、国内の除外ワードに「箱なし」などを入れて揃えると精度が上がります。

### 実売価格と回転率（推定）

eBay の落札データ（Sold）は API では取得できません。旧 Finding API の `findCompletedItems` は 2025 年 2 月に廃止され、後継の Marketplace Insights API は eBay の承認制（新規受付なし。このアプリのキーでは `invalid_scope`）です。eBay のサイトを自動で読み取る方法（スクレイピング）は eBay の利用規約で禁止されているため使いません。

そこで、使える公式 API（Browse API）の範囲で次のように推定しています。

- 集計に使った eBay の出品のうち、おすすめ順の上位 8 件について出品の詳細（`getItem`）を取得し、「その出品で売れた数」（`estimatedSoldQuantity`）と出品日を調べます。売れた数が分かるのは、**同じ商品を複数個まとめて出品している場合**（新品・ショップの在庫など）だけです。
- **推定販売数（月）** = 各出品の「売れた数 ÷ 出品日数 × 30」の合計（出品日数は 7 日以上として計算）。
- **売れている出品の価格** = 売れた実績のある出品の価格を、売れた数で重み付けした中央値。実売価格に最も近い目安として、利益計算の売価の初期値にしています（なければ出品中の安い方から 25% で代用し、カードに表示します）。
- **回転率ランク**: S（推定 月 5 個以上）・A（月 1〜4 個）・B（月 1 個未満・売れた実績あり）・C（まとめ出品はあるが売れた実績なし）・?（販売数が分からない＝中古の 1 点ものなど）。「?」は C（リスク高）とは区別しています。中古品は各商品の「eBay 落札済み」から確認してください。
- 「お宝の条件」の「回転率ランク」で、お宝にするランクの下限を選べます（初期値は問わない。下限を選ぶと「?」はお宝になりません）。
- 出品ごとの販売数は 6 時間使い回します。1 商品あたり eBay API を最大 9 回（検索 1 回＋詳細 8 回）使います（1 日 5,000 回まで）。

### 付属品・アクセサリーの誤マッチング対策

型番で検索すると、本体（数万円）と一緒に「液晶保護フィルム」「専用ケース」などの付属品（数百〜数千円）も見つかり、計算上「利益率 90% の超お宝」に見えてしまいます。次の 3 段階で防いでいます。

1. **検索の時点で除く（商品指定）**: 先に eBay の相場を調べ、その「付属品とみなす割合」（初期値 25%）を国内の最低価格として楽天・Yahoo! を検索します（例: eBay 相場 $500・為替 150 円なら 18,750 円以上）。安い付属品で検索結果の枠が埋まらず、本体が多く見つかります。検索条件の下に「付属品を除くため ¥◯ 以上で検索」と表示されます。
2. **タイトルで除く（商品指定・その他）**: 「保護フィルム」「ケース」「カバー」「キャップ」「バッテリー」「ストラップ」「説明書」「箱のみ」「攻略本」や、「ZV-E10用」「E10専用」のように型番の直後に「用・専用」が付く出品を除きます。ただし中古の本体は「元箱・説明書・バッテリー付き」「ストラップ欠品」「グリップセット」のように付属品の名前を含むので、「付き・付属・欠品・セット」などが続くときは除外しません。「未使用」「Vlog用カメラ」「フィルムカメラ」も除外しません。
3. **価格の比率で除く（すべての種類）**: 国内価格が eBay 相場（中央値）の「付属品とみなす割合」未満の商品は仕入れ先に選びません。すべての国内商品がそれより安い場合はお宝にせず、「付属品・別商品の可能性」と表示します。割合は「お宝の条件」で変更でき、0 にすると無効になります。

Yahoo! の検索 API には除外キーワードの指定がなく、カテゴリ ID はジャンルごとに調べて指定する必要があるため、カテゴリでの絞り込みは使っていません。

同じ型番の別モデル・セット（例: `ZV-E10` に対する `ZV-E10 II` やレンズキット）は付属品と違って高いので上の対策では除けません。本体だけを調べたいときは、検索キーワードに「ボディ」を入れ、除外ワードに `II レンズキット` などを入れてください。

### 型番・商品名で調べる（直接入力）

画面上部の「型番・商品名で調べる」に、1 行に 1 商品ずつ書いて「調べる」を押すだけで、商品指定のリサーチができます。

| 書き方 | 国内の検索 | eBay の検索 |
|---|---|---|
| `BOSS DS-1` | BOSS DS-1 | BOSS DS-1 |
| `キヤノン AE-1` | キヤノン AE-1 | AE-1（日本語を除いた型番を自動で使用） |
| `ニコン F3 ボディ \| Nikon F3 body` | ニコン F3 ボディ | Nikon F3 body（`\|` の右側） |
| `4521329362342` | JAN | JAN |

- eBay は英語で検索するため、日本語の商品名だけで型番（英字と数字を含む 3 文字以上）がない行は、`|` の後に英語を書くよう案内します。
- 自動で決めた eBay キーワードは確認欄に「（自動）」と出ます。型番だけだと別の商品も混ざる場合（例: `C3000XG` は複数のリールにある）は、`| Shimano 22 Stella C3000XG` のように英語を書き足してください。
- 「検索条件として保存する」にチェックを入れると、検索条件の一覧に追加され（同じ名前は上書き）、次からは「実行」だけで調べ直せます。

### CSV でまとめて登録・管理

「CSV でまとめて登録・書き出し」から、検索条件を CSV で一括登録・書き出しできます。

- **テンプレート**: 入力例（カメラ・釣具・レトロゲーム・エフェクター・ポケカ）入りの CSV をダウンロードします。
- **今の条件を書き出す**: 登録済みの検索条件を CSV で保存します（Excel で開けるよう BOM 付き UTF-8）。編集して読み込み直せます。
- **読み込み**: CSV ファイルを選ぶか、表を貼り付けます（タブ区切りも可）。Excel で保存した Shift_JIS の CSV もそのまま読めます。登録前に「読み込める件数・上書きされる件数・読み込めない行（行番号と理由）」を確認できます。
  - 追加: 同じ名前の条件は上書き、それ以外は追加
  - すべて置き換え: 今の条件をすべて消して読み込んだ内容にする

| 列 | 内容 | 例 |
|---|---|---|
| 名前 | 必須。同じ名前は上書きの目印 | Nikon F3 ボディ |
| ジャンル | 一覧の絞り込み・ジャンルごとの実行に使う | カメラ |
| 種類 | 商品指定（省略時）・未開封BOX・PSA10・シングル・その他 | 商品指定 |
| 検索キーワード | 楽天・Yahoo! で検索する言葉（商品指定で JAN があれば省略可） | ニコン F3 ボディ |
| JAN | 商品指定のみ。13 桁はチェックデジットも確認 | （13 桁の数字） |
| eBayキーワード | 英語。商品指定で JAN がなければ必須 | Nikon F3 body |
| 状態 | 商品指定のみ。新品（省略時）・中古・すべて | 中古 |
| 除外ワード | スペース区切り | 箱なし 説明書なし |
| 最低価格・最高価格 | 国内価格の範囲（円） | 10000 |
| 国際送料 | この商品の国際送料（円） | 3000 |
| eBay調査件数 | 商品指定以外で、eBay を調べる商品数の上限 | 15 |

Excel で JAN の列が `4.52E+12` のように表示されたまま保存すると、桁が失われて読み込めません。JAN の列は「文字列」の書式にしてから入力してください。

画面の「ジャンル」で絞ると、一覧・リサーチの実行・結果がそのジャンルだけになります。実行中は「中止」で止められます（実行中の条件が終わったところで止まります）。

### 注意

- **eBay の落札履歴（Sold）は API では取得できません。** 落札データの API（Marketplace Insights API）は eBay の審査が必要で、このアプリのキーでは使えません（`invalid_scope`）。相場は出品中（即決）の価格で、各商品の「eBay 落札済み」ボタンから eBay のサイトで落札価格を確認できます。
- 国内の価格は API で取得した範囲（楽天 30 件・Yahoo! 50 件）での最安値です。
- 「未開封BOX」は JAN コードがない出品（オリパ・くじなど）を自然に除けますが、JAN が書かれていない正規品も対象外になります。
- 楽天・Yahoo! の API の利用規約に従い、画面の下にクレジット（Supported by Rakuten Developers / Webサービス by Yahoo! JAPAN）を表示しています。
- 検索条件・お宝の条件・最後の結果は、そのブラウザ（localStorage）に保存されます。

### 楽天 API の設定（2026 年の移行後）

楽天の旧 API（`app.rakuten.co.jp`）は 2026 年 5 月に停止し、新しい API（`openapi.rakuten.co.jp`）ではアプリ ID・アクセスキーに加えて、**リクエスト元のサイトがアプリの「許可されたWebサイト」に登録されていること**が必要になりました。

楽天の「Webアプリケーション」はブラウザから直接呼ぶ前提の仕組みなので、このアプリは**楽天だけはスマホ・パソコンのブラウザから直接検索**し、その結果をサーバーに渡します（Yahoo! と eBay はサーバーから呼びます）。ブラウザが今開いているサイトの URL を自動で送るので、サーバーから送るときのような URL のずれが起きません。

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/) で新しくアプリを登録し、**アプリケーション ID** と **アクセスキー** を取得する（移行前に作ったアプリの ID は使えません）。
2. アプリ設定の **「許可されたWebサイト」** に、Vercel の **本番の URL**（Vercel の Settings → Domains に出ている、変わらない URL）を登録する。Vercel がデプロイごとに作る URL（`price-gap-research-86nf2ix1j-….vercel.app` のように途中に英数字が入るもの）は更新のたびに変わるため、登録しても次の更新で使えなくなります。このアプリは、デプロイごとの URL で開かれると自動で本番の URL へ移ります（`VERCEL_ENV=production` のときだけ。Vercel が自動で設定する `VERCEL_PROJECT_PRODUCTION_URL` を使います）。
3. Vercel の環境変数に `RAKUTEN_APP_ID` と `RAKUTEN_ACCESS_KEY` を登録して Redeploy する。

- 楽天のキーは、合言葉でログインしたブラウザにだけ `/api/rakuten/credentials` から渡します。楽天のキーは登録したサイトからしか使えないため、ブラウザに渡すのは楽天が想定している使い方です。
- エラーのときは画面の注意に、原因（アクセスキー違い・アプリ ID 違い・許可されたWebサイト未登録など）と、楽天に送ったサイト URL が表示されます。その URL を「許可されたWebサイト」に登録してください。

`.env.local` は `.gitignore` で除外されているため GitHub にはアップロードされません。キーをチャットやコードに直接書かないでください。

## 利益の計算式

```
eBay 売上   = eBay 売価（購入者負担の送料は 0 として計算）     [USD]
eBay 手数料 = eBay 売上 × (落札手数料率 + 海外取引手数料率) + 1注文あたり固定手数料  [USD]
入金額      = (eBay 売上 − eBay 手数料) × 為替レート           [円]
仕入れ合計  = 国内最安値 + 国内送料 + 国際送料                  [円]
利益        = 入金額 − 仕入れ合計                               [円]
利益率      = 利益 ÷ (eBay 売上 × 為替レート)
```

手数料率・送料の初期値は目安です。画面の「計算条件」で、最新の eBay 手数料や実際の送料に合わせて変更してください（国際送料は検索条件ごとにも設定できます）。
