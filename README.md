# price-gap-research

**Amazon Japan・楽天市場・Yahoo!ショッピング**の国内 3 モールで、同じ商品の価格差を調べる Web アプリです（国内完結のマルチアービトラージ）。

検索・照合は **JAN コード（EAN）だけ**で行い、タイトル検索による別商品・付属品の誤判定をなくしています。1 つの JAN について 3 モールの新品・在庫ありの価格とポイントをまとめて取得し、方向を固定せずに「どこで仕入れてどこで売ると一番得か」を自動で判定して、

> **[推奨] Yahoo!仕入れ ➔ Amazon FBA販売 ｜ 見込み利益 ¥4,800（利益率 22%）｜ 回転率 S ｜ リスク: なし**

のように結果の一番上に表示します。Amazon の販売価格は 90 日平均で保守的に見込み、Keepa のデータから「出品者急増（値崩れ）」「Amazon 本体の復帰」「不人気バリエーション」などのリスクを自動で判定して、危ない商品は推奨から外します。

## 必要なもの

- [Node.js](https://nodejs.org/) 22 以上（`node -v` でバージョンを確認できます）

## 使い方（ローカルで動かす）

```bash
npm install      # 初回のみ：必要なライブラリをインストール
cp .env.example .env.local   # キーを書く（下の「必要な環境変数」）
npm run dev      # 開発用サーバーを起動
```

ブラウザで http://localhost:3000 を開きます。止めるときはターミナルで `Ctrl + C` を押します。

JAN の一覧・計算の前提・最後の結果は、そのブラウザの中（localStorage）だけに保存されます。

### プロキシ環境で動かす場合

社内ネットワークなど HTTP プロキシ（`HTTPS_PROXY` 環境変数）経由でしか外に出られない環境では、Node.js の `fetch` がプロキシを使うように `NODE_USE_ENV_PROXY=1` を付けて起動します（Node.js 22.21 以上）。

```bash
NODE_USE_ENV_PROXY=1 npm run dev
```

## 合言葉（ログイン）

URL を知っている第三者に Amazon・楽天・Yahoo! の API 利用枠を使われないよう、サイトを開くと合言葉を求めます。合言葉は環境変数 `APP_PASSWORD` で設定します。

- 合言葉が合うと、そのブラウザは 30 日間ログインしたままになります。右上の「ログアウト」で解除できます。
- `APP_PASSWORD` を変えると、それまでログインしていたブラウザはすべてログアウトされます。
- 同じ接続元から 5 回まちがえると、15 分間ログインできなくなります（簡易的な総当たり対策）。
- **本番で `APP_PASSWORD` が未設定だと、安全のためサイトも API も使えない状態になります**（エラー表示）。`npm run dev` では未設定ならログインなしで使えます。
- 4 桁の PIN のような短い合言葉は総当たりで破られやすいので、12 文字以上をおすすめします。

## Vercel で公開する（スマホで使う）

1. [Vercel](https://vercel.com) に GitHub アカウントでログインし、「Add New → Project」でこのリポジトリを Import します。
2. 「Environment Variables」に、下の「必要な環境変数」を登録します（`APP_PASSWORD` は必須）。
3. 「Deploy」を押すと `https://〇〇.vercel.app` の URL ができます。スマホで開き、合言葉を入力します。

`NODE_USE_ENV_PROXY` は Vercel では不要です。環境変数を後から変えたときは、Deployments 画面から「Redeploy」すると反映されます。
eBay 時代の `EBAY_CLIENT_ID`・`EBAY_CLIENT_SECRET`・`EBAY_ENVIRONMENT` はもう使わないので、Vercel から削除して構いません。

| 名前 | 内容 |
|---|---|
| `APP_PASSWORD` | サイトを開くときの合言葉 |
| `KEEPA_API_KEY` | Keepa の API キー（Amazon の価格・ランキング・月の販売回数・手数料） |
| `AMAZON_SP_CLIENT_ID` | （任意）Amazon SP-API（LWA）のクライアント ID |
| `AMAZON_SP_CLIENT_SECRET` | Amazon SP-API（LWA）のクライアントシークレット |
| `AMAZON_SP_REFRESH_TOKEN` | アプリを自分のセラーアカウントで承認したときのリフレッシュトークン（`Atzr\|` で始まる） |
| `RAKUTEN_APP_ID` | 楽天ウェブサービスのアプリケーション ID |
| `RAKUTEN_ACCESS_KEY` | 楽天ウェブサービスのアクセスキー（`RAKUTEN_APP_ID` と同じアプリのもの） |
| `RAKUTEN_SITE_URL` | （任意）サーバーから楽天を呼ぶときに送るサイト URL。未設定なら Vercel の本番 URL を使います |
| `RAKUTEN_AFFILIATE_ID` | （任意）楽天アフィリエイト ID |
| `YAHOO_CLIENT_ID` | Yahoo!デベロッパーネットワークの Client ID |

どれかのモールのキーが未設定でも、設定されているモールだけで比較します（画面に注意が出ます）。Amazon は Keepa か SP-API のどちらかがあれば使えます。どちらもなければ楽天 ⇄ Yahoo! だけの比較になります。

### Keepa の設定

Amazon の情報は [Keepa API](https://keepa.com/#!api) で取得できます（大口出品アカウントは不要）。API プランを契約し、表示されたキーを `KEEPA_API_KEY` に登録して Redeploy します。

- 1 つの JAN を調べるごとに、`stats=90`・`buybox=1`・直近 15 日の履歴（`history=1&days=15`）で 1 回リクエストします。カート価格の分のトークンが追加でかかります（Keepa のプランの説明で確認してください）。バリエーション商品は、親 ASIN（1 トークン）と兄弟 ASIN（最大 50 個）をさらに調べます。兄弟は `asin=A,B,C…` で 100 件ずつまとめて 1 回で取得し、履歴は付けません（`history=0`）。Keepa は 1 商品につき 1 トークンかかるので、兄弟が N 個なら「親 1 ＋ 兄弟 N−1（調べている商品自身は取得済みなので除く）」トークンです。同じ親の結果は 6 時間使い回すので、同じ商品の色違い・サイズ違いを続けて調べても追加のトークンはかかりません。トークンはプランごとに 1 分あたりの量で回復し、足りないときは画面に「◯秒後に回復」と出ます。
- 取得する値: 新品の最安値（Amazon 本体・FBA・自社発送の送料込み）、**カート価格と 90 日平均**、カートを持っている出品者（FBA／自己発送／Amazon 本体）、新品の出品者数と **7 日前・14 日前の出品者数**、売れ筋ランキング、**過去 30 日・90 日のランキング変動回数（Sales Rank Drops）**、Amazon の「過去 1 か月で ◯ 点以上購入」、**過去 90 日の Amazon 本体のカート獲得率・在庫切れ率**、バリエーションごとの購入数、販売手数料率と FBA 配送代行手数料。
- Keepa は出品ごとのポイントが分からないため、Amazon で仕入れるルートのポイントは 0 として計算します（必要なら「上乗せポイント」で調整）。
- SP-API も設定している場合は、価格・ポイント・手数料は SP-API、販売回数は Keepa を使います。

Keepa の API はキーを URL のパラメーターで送る仕様のため、サーバーからだけ呼び、URL をログや画面に出さないようにしています。

### Amazon SP-API の設定（任意）

Amazon の価格・売れ筋ランキング・FBA 手数料は、Keepa のほかに公式の [Selling Partner API](https://developer-docs.amazon.com/sp-api/) で取得します（スクレイピングはしません）。

1. セラーセントラルの**大口出品**アカウント（月額 4,900 円）が必要です。
2. セラーセントラルの「アプリとサービス → アプリの開発」で開発者登録をし、自分のアカウント専用の「プライベートアプリ」を作ります。ロールは **「商品の価格設定（Pricing）」「商品カタログ（Product Listing）」** を付けます。
3. アプリの「LWA 認証情報」のクライアント ID・クライアントシークレットと、「承認」で発行されるリフレッシュトークンを、上の 3 つの環境変数に登録します。

- 2023 年 10 月以降、AWS の IAM・署名（SigV4）は不要です（LWA のアクセストークンだけで呼びます）。
- 使う API: Catalog Items 2022-04-01（JAN → ASIN・商品名・画像・売れ筋ランキング）、Product Pricing v0 `getItemOffers`（新品の出品・カート価格・ポイント）、Product Fees v0（FBA で売るときの手数料見積もり）。日本は極東エンドポイント（`sellingpartnerapi-fe.amazon.com`）・マーケットプレイス `A1VC38T7YXB528` です。
- `getItemOffers` は **2 秒に 1 回まで**の制限があるので、1 件あたり 3〜5 秒かかります。上限を超えたときは 1 回だけ待ってやり直します。

### 楽天 API の設定（2026 年の移行後）

楽天の旧 API（`app.rakuten.co.jp`）は 2026 年 5 月に停止し、新しい API（`openapi.rakuten.co.jp`）ではアプリ ID・アクセスキーに加えて、**リクエスト元のサイトがアプリの「許可されたWebサイト」に登録されていること**が必要になりました。

楽天の「Webアプリケーション」はブラウザから直接呼ぶ前提の仕組みなので、このアプリは**楽天だけはスマホ・パソコンのブラウザから直接検索**し、その結果をサーバーに渡します（Amazon と Yahoo! はサーバーから呼びます）。ブラウザが今開いているサイトの URL を自動で送るので、サーバーから送るときのような URL のずれが起きません。

1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/) で新しくアプリを登録し、**アプリケーション ID** と **アクセスキー** を取得する（移行前に作ったアプリの ID は使えません）。
2. アプリ設定の **「許可されたWebサイト」** に、Vercel の **本番の URL**（Vercel の Settings → Domains に出ている、変わらない URL）を登録する。Vercel がデプロイごとに作る URL（`price-gap-research-86nf2ix1j-….vercel.app` のように途中に英数字が入るもの）は更新のたびに変わるため、登録しても次の更新で使えなくなります。このアプリは、デプロイごとの URL で開かれると自動で本番の URL へ移ります（`VERCEL_ENV=production` のときだけ。Vercel が自動で設定する `VERCEL_PROJECT_PRODUCTION_URL` を使います）。
3. Vercel の環境変数に `RAKUTEN_APP_ID` と `RAKUTEN_ACCESS_KEY` を登録して Redeploy する。

- 楽天のキーは、合言葉でログインしたブラウザにだけ `/api/rakuten/credentials` から渡します。楽天のキーは登録したサイトからしか使えないため、ブラウザに渡すのは楽天が想定している使い方です。
- エラーのときは画面の注意に、原因（アクセスキー違い・アプリ ID 違い・許可されたWebサイト未登録など）、楽天に送ったサイト URLが表示されます。
- 楽天は JAN そのものをキーワードにして検索します。楽天の検索キーワードには「1 つの単語は半角 2 文字以上（漢字は 1 文字以上、ひらがな・カタカナ・記号は 2 文字以上）・全体で半角 128 文字（全角は 2 文字）まで」という決まりがあり、守らないと `keyword is not valid` になります。アプリは楽天に送る前に、使えない 1 文字の単語を除き、長すぎる分を後ろから削ります。

`.env.local` は `.gitignore` で除外されているため GitHub にはアップロードされません。キーをチャットやコードに直接書かないでください。

## 使い方（画面）

1. **JAN を追加**: 1 行に 1 つ貼り付けます（JAN の後ろに商品名などのメモを書いても OK）。チェックデジットが違う JAN は読み込みません。Excel の CSV（Shift_JIS）も読めます。一覧は CSV に書き出せます。
2. **JAN を探す**: JAN が分からないときは、商品名・型番で Yahoo!ショッピングを検索して JAN を見つけるか、**楽天のリアルタイムランキング**から JAN が書かれている売れ筋商品を拾って登録できます。
3. **すべて調べる**: 登録した JAN を 1 件ずつ 3 モールで調べます（途中で「中止」できます）。
4. **結果**: 利益の大きい順に並び、各商品の一番上に**最適ルート**（条件を満たすものは緑）が出ます。その下に 3 モールの最安値・ポイント・在庫数・リンク、「すべてのルート」の利益の比較が出ます。

## 全自動バルクリサーチ（型番・JAN の入力なし）

画面上部のタブを「全自動バルクリサーチ」にすると、ボタン 1 つで市場から商品を集めて、そのまま 3 モールを一括比較します。

| ソース | 集め方 | 使う API |
|---|---|---|
| Keepa条件抽出 | Amazon の売れ筋ランキング 5 万位以内・**Amazon 本体が販売していない**・新品出品者 2〜10 人・カート価格 1,500 円以上・バリエーションは 1 つだけ、をランキング順に | Keepa Product Finder（`/query`）→ `/product?asin=A,B,…`（100 件ずつ・履歴なし）で JAN に変換 |
| 楽天 高ポイント | ポイント **5 倍以上**・在庫ありの商品を、レビューの多い順に（説明文に JAN が書かれている商品だけ） | 楽天商品検索（`pointRateFlag=1&pointRate=5`）。楽天スーパーDEAL を取り出す公開 API はないため、ポイント倍率で代用 |
| Yahoo!ランキング | 評価の高い人気商品ランキング（JAN つき） | Yahoo! `highRatingTrendRanking` |

- **カテゴリ**: すべて・家電・おもちゃ・ビューティー・日用品。Amazon・Yahoo! のカテゴリ ID は、カテゴリ名で各 API（Keepa のカテゴリ一覧・Yahoo! のカテゴリ ID 取得）から実行時に選びます。楽天はジャンル ID を使います。
- **取得件数**: 20・50・100 件（選んだソースで等分。重複する JAN は 1 つにまとめます）。
- **バッチ処理**: 集めた JAN を 1 件ずつ「JAN 完全一致の 3 モール比較」に回します。楽天の制限（1 秒 1 回）のため 1.1 秒以上間を空け、Keepa のトークンが足りなくなったら回復を待って（最大 5 分）同じ JAN をやり直します。途中で「中止」できます。
- **進捗**: 「23/50 件処理中…（利益商品 4 件発見）」とバーで表示します（画面上部に固定）。
- **画面を閉じたとき**: 調査はスマホのブラウザの中で動いているので、画面を閉じる・別のアプリに切り替えると止まります。どこまで進んだかを保存しているので、開き直すと「続きから再開」できます。調べている間は画面が自動で消えないようにしています（Screen Wake Lock。iPhone は iOS 16.4 以降）。
- **Keepa のキャッシュ**: 一度調べた Amazon（Keepa）のデータはブラウザに保存し、設定の時間内（初期値 12 時間。6・12・24 時間・使わないから選択）に同じ JAN を調べるときはサーバーに送り返して Keepa を呼びません（トークン 0）。楽天・Yahoo! は毎回最新を取ります。個別の「調べる」「調べ直す」は必ず Keepa で取り直します。サーバー側でも同じ JAN を 12 時間使い回します（同じサーバーが続けて使われている間）。
- **リクエストの軽量化**: 履歴（csv）は出品者数の推移を見る直近 15 日分だけ（`days=15`）、バリエーションの兄弟は履歴なし（`history=0`）で取得します。Keepa のトークンは「商品 1 つにつき」かかるので、履歴を減らすと主に応答が軽くなります（トークンが減るのはキャッシュとバリエーション判定の節約）。
- **自動ウェイト**: 残りトークンの見込みが 10 以下になったら、Keepa を呼ぶ前に「トークン回復待ち（残り約 ◯ トークン・◯ 秒後に自動再開）」と表示して待ち、回復したら自動で続けます（キャッシュを使う商品は待たずに進めます）。
- **トークン残量の表示**: 進捗と全自動リサーチの画面に「Keepa 残り ◯ トークン・次の回復まで ◯ 秒（1 分ごとに +◯）」を 1 秒ごとに表示します（最後に分かった残り数と回復ペースからの見込み）。
- **Keepa のトークン節約**: 進捗に残りトークンと 1 分あたりの回復量を表示します。「すべて調べる」・全自動リサーチでは 6 時間以内に調べた商品を飛ばします（設定で切り替え）。バリエーション判定は、残りトークンから予備 20 を引いた分で足りるときだけ行い、足りないときは省略して注意を出します（あとで「調べ直す」と判定）。
- **結果**: 見込み利益順・利益率順・回転率順で並び替え、「利益 ◯円以上のみ」「リスクなしのみ」「推奨条件クリアのみ」「今回の全自動リサーチ分だけ」で絞り込めます。集めた商品は「調べる JAN」の一覧にも入るので、あとから調べ直せます。
- **トークン**: Keepa条件抽出は Product Finder（Keepa の料金表のトークン）＋ JAN への変換（1 商品 1 トークン）＋比較（1 件ごと）でトークンを使います。プランのトークン量に合わせて件数を選んでください。

## JAN による照合（誤判定をなくす仕組み）

| モール | 照合のしかた |
|---|---|
| Amazon | カタログを JAN で検索し、商品ページに登録された EAN が JAN と一致するものだけ。同じ JAN に複数の ASIN があるときは一番売れている ASIN を使います |
| Yahoo! | `jan_code` で検索し、商品データの `janCode` が完全一致するものだけ |
| 楽天 | 楽天の API には JAN の項目がないため、JAN で検索し、商品名・説明文に JAN がそのまま（前後に数字が続かずに）書かれているものだけ |

さらに「2個セット」「×3本」「まとめ買い」「ケース販売」など、1 個の値段ではない出品は除きます（Amazon の商品名自体がセット商品のときは除きません）。どのモールも**新品・在庫あり**だけを対象にします。

**新品だけにする仕組み**: Amazon は API で新品の出品だけを取得します。楽天の API には新品・中古の区別がなく、Yahoo! もストアの登録しだいなので、次のどれかに当てはまる出品は除きます。

- Yahoo! の商品データが中古（`condition: used`）
- 商品名に「中古・USED・開封済・未使用品・展示品・アウトレット・訳あり・ジャンク・難あり・箱潰れ・美品・整備済・ランクA／Bランク」など（「新品未使用」「無印良品」は対象外）
- 説明文に「【中古】」「中古品」「商品ランク」「状態ランク」などのはっきりした表記（「中古品ではありません」は対象外）

## 利益の計算式

```
実質仕入れ値 = 商品価格 + 送料 − ポイント
ポイント     = (モールが表示しているポイント + 商品価格 × 上乗せ%) × ポイントの価値%
利益         = 販売価格 − 販売手数料 − 発送・納品コスト − 実質仕入れ値
利益率       = 利益 ÷ 販売価格
```

- **ポイント**: 楽天はショップのポイント倍率（税抜価格の 1% × 倍率）、Yahoo! はストアポイント（PayPay ポイント（期間限定）。API の `lyLimitedBonusAmount`。2025 年 2 月から古い `bonusAmount` は 0 固定）、Amazon は出品のポイントを自動で使います。楽天 SPU・LYP 会員・キャンペーンなど人によって違う分は「計算の前提」の**上乗せポイント**に入れてください。
- **販売価格（Amazon・保守的計算）**: 楽天・Yahoo! はそのモールの最安値。Amazon は次の順で決めます。
  1. 基本は**カート価格**（なければ FBA 最安値 → 最安値）。
  2. **安全値**: 「現在のカート価格」と「90 日平均カート価格」の**低い方**を使います（たまたま今だけ高騰している商品を仕入れないため。設定でオフにできます）。
  3. **FBA プレミアム**: カートを**自己発送（FBM）**の出品者が持っているときは、FBA なら少し高くてもカートを取れるので、2. の価格に **+5%**（設定で 0〜10%）を上乗せします。ただし FBA の出品がそれより安く出ていれば、その価格までにします。
- **Amazon の手数料**: Keepa の販売手数料率 × 販売価格 ＋ FBA 配送代行手数料（SP-API があればその見積もり）。どちらもないときは「販売手数料 %」＋「FBA 配送代行手数料（円）」で計算します。FBA への納品送料（1 個あたり）は別に設定します。
- **楽天・Yahoo! で販売**: 出店している前提で、システム利用料・決済手数料などを合計した割合と、お客様への送料で計算します。**出店していないモールは「販売先」のチェックを外してください。**
- **回転率**: Amazon の月の販売回数の目安（Keepa の 30 日のランキング変動回数、90 日の回数 ÷ 3、Amazon の「過去 1 か月で ◯ 点以上購入」の一番大きい値）から S（月 10 個以上・即売れ）・A（3〜9 個・高回転）・B（1〜2 個）・C（販売実績なし・低回転）を付けます。販売回数が分からないときは売れ筋ランキング（5,000 位・3 万位・10 万位以内）で決めます。どちらも目安です。楽天・Yahoo! で売るルートは回転率が分からないため「?」になります。
- 送料別・条件付き送料無料の商品は「送料別のときの送料」を足して計算します（Amazon の出品は送料が分かるのでその金額）。

- **リスク判定（Amazon で売るルート）**: Keepa のデータで次を判定し、⛔（危険）は推奨から外します（設定で外さないこともできます）。⚠（注意）は表示だけです。

  | リスク | 判定 | 理由 |
  |---|---|---|
  | ⛔ 出品者急増 | 新品出品者が 7 日または 14 日前より **30% 以上**（かつ 2 人以上）増えた | セール後に全国のせどらーが一斉に仕入れると、1〜2 週間後に値崩れする |
  | ⛔ Amazon本体の復帰 | 過去 90 日に Amazon 本体が**カートを 20% 以上**取っていて、今は在庫切れでいない | 補充された瞬間にカートを奪われて売れなくなる（在庫切れ率も表示） |
  | ⛔ 不人気バリエーション | 色・サイズ違いの中で、この商品の購入数（なければレビュー数）の**シェアが 10% 未満** | ランキングは全バリエーション共通なので、別の色だけが売れていることがある |
  | ⚠ バリエーション要確認 | バリエーションが 50 個より多いなどで、シェアを判定できなかった | Amazon で売れている色・サイズを確認する |
  | ⚠ Amazon本体が販売中 | Amazon 本体が今販売している | カートを取りにくい |
  | ⚠ 一時的な高騰 | 現在のカート価格が 90 日平均より 20% 以上高い | 安全値（90 日平均）で計算済み |

  しきい値（30%・20%・10%）は「計算の前提」で変更できます。
- **最適ルート**: 推奨の条件（利益・利益率・回転率・リスク）を満たすルートの中から、「利益 × 回転率の重み（S 1.0・A 0.85・B 0.6・C 0.3・不明 0.5）」が一番大きいものを選びます。利益が少し小さくてもよく売れるルートを優先するためです。結果の一番上に「最適ルート一覧」として並び、タップすると各商品の詳細へ移動します。

初期値はすべて目安です。画面の「計算の前提・推奨の条件」で実際の条件に合わせて変更してください。
